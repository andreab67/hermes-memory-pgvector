# 1.0 readiness review — hermes-memory-pgvector

Date: 2026-09-26. Reviewed: `main` at `02c4481` (v0.5.5 plus the M4.6 roadmap commit).
Upstream contract checked against `NousResearch/hermes-agent` `main` at `d0288be5` (2026-09-26).

v0.5.5 is not ready to ship as 1.0: none of the four M6 items has started, and this review
found four high-severity defects. The execution plan is
[`docs/release/PLAN-1.0.md`](../release/PLAN-1.0.md).

## Verification

Every source file, the four migrations, `ROADMAP.md`, the README and the 2026-09-07 review were
read. The full suite ran against Ubuntu PostgreSQL 16 with pgvector 0.8.6 built from source:
**217 passed, 1 skipped** (the skip needs an embed endpoint). H1, H3, M1 and L10 were reproduced
against a live database; the reproductions are in [`repro-2026-09-26/`](repro-2026-09-26/) and
exit 1 while the bug exists, 0 once fixed. L7 was tested at 20k rows and did not reproduce.
Upstream-contract findings (H2, H4, M4) come from reading hermes-agent `agent/memory_provider.py`,
`agent/memory_manager.py`, `agent/agent_init.py` and `plugins/memory/__init__.py`. Findings marked
"code reading" are unexecuted.

## Findings

| ID | Severity | Finding | Where | Evidence |
| --- | --- | --- | --- | --- |
| H1 | High | `migrate` aborts on any runtime role not named `hermes`. 002 runs `GRANT … TO hermes` unguarded, so 003 and 004 never run. The README says non-`hermes` roles just get a NOTICE. | `migrations/002_agent_attribution.sql` (GRANT block) | Reproduced: `error: role "hermes" does not exist`, exit 1, only 001's objects present. `repro_h1_migrate_role.py` |
| H2 | High | replace/remove ignore upstream's `metadata["previous_content"]` (the exact entry the built-in store edited) and match `old_text` as a substring, lowest id first. The mirror keeps stale rows MEMORY.md no longer has, so the wrong row is deleted or rewritten. | `__init__.py:986`, `store.py:252–339` | Upstream `memory_manager.notify_memory_tool_write` sends `previous_content`; the `MemoryProvider.on_memory_write` docstring says `old_text` "is not authoritative identity". |
| H3 | High | Backfill re-fetches failing rows every batch. If `batch_size` rows at the lowest ids fail permanently, the loop stops and every later row stays NULL forever. `failed`/`processed` count a row once per batch. | `store.py:1011–1050` | Reproduced: 10 failing + 25 good rows, batch 10 → 0 succeeded, 25 stuck. 3 failing rows → `failed: 15`, `processed: 40` for 28 rows. `repro_h3_backfill.py` |
| H4 | High | `prefetch()` embeds synchronously with a 10 s timeout (20 s worst case under `auto`). Upstream runs external prefetch with an 8 s budget and skips the provider on later turns until the stuck call returns. On the reference endpoint (6–17 s per the README) ambient recall drops out. | `__init__.py:627–634`, `DEFAULTS["embed_timeout"]` | Upstream `_EXTERNAL_PREFETCH_TIMEOUT_S = 8.0`; `queue_prefetch()` exists for this and is not implemented. |
| M1 | Medium | `UNIQUE(agent_identity, target, content)` is a btree on raw text: an entry of roughly 2.7 KB+ that does not compress cannot be inserted. In bulk import the exception also aborts the rest of that file. | `001_schema.sql`, `store.py:639` | Reproduced: 3,000-char entry → `ProgramLimitExceeded: index row size … exceeds btree version 4 maximum 2704`. `repro_m1_unique_limit.py` |
| M2 | Medium | Backfill's UPDATE is unguarded: a `replace()` landing while backfill embeds the old text leaves new content with the old embedding. | `store.py:1038` | Code reading. |
| M3 | Medium | Shutdown waits 5 s, but one write can spend up to 60 s embedding (`embed_write_timeout` 30 s, `max_total` 2×). On a slow endpoint every queued write is abandoned at restart. | `writer.py` `shutdown`, `__init__.py:559` | Code reading. |
| M4 | Medium | `agent_context` (`primary`/`cron`/`subagent`) is ignored; upstream says to skip writes for non-primary contexts. | `initialize()` | Upstream `agent/agent_init.py` passes it. |
| M5 | Medium | Delegation turns store the child's session id in `conversations.parent_session_id`, the reverse of migration 002's definition of that column. | `__init__.py:852` | Code reading. |
| M6 | Medium | `health()` and `system_prompt_block()` run full `COUNT(*)` scans on every session init. | `store.py:840–852`, `__init__.py:604–605` | Code reading. |
| M7 | Medium | Identities are case-sensitive: `Marketing` and `marketing` are separate themes; the allow-list check is case-sensitive too. | `identity.py` `normalize_identity` | Code reading. |
| L1 | Low | A real-looking Colorado Springs phone number (`1719271…`) appears in docstrings that ship in the wheel, and in tests. | `identity.py:12,37`, `__main__.py:11`, `tests/test_identity.py`, `tests/test_store_v04.py` | If it came from production, replace it and consider the git history. |
| L2 | Low | Default `embed_url` is a private LAN address (`192.168.100.50`). | `__init__.py:206` | Wrong default for public users; leaks topology. |
| L3 | Low | Stale text: config schema says a full queue drops the "oldest" writes (it drops the newest); module docstring says one tool; `normalize_identity` reason list omits `group-bucket`. | `__init__.py:32,1482`, `identity.py` | Code reading. |
| L4 | Low | `backfill` exits 0 when the endpoint is down or rows remain; CLI commands never close their pools. | `__main__.py:317–333` | Code reading. |
| L5 | Low | `AsyncWriter._stop` is never set; `stats()` is never surfaced. | `writer.py` | Dead code. |
| L6 | Low | Pure-vector paths do not filter `embedding IS NOT NULL`; with `hybrid_search: false` NULL rows can fill the tail with `score: null`. | `store.py:373–423, 705–747` | Code reading. |
| L7 | Low | Theme-filtered ANN at scale: HNSW post-filters, so a mid-size theme in a very large table can come back short. | `store.py` search paths | Not reproduced at 20k rows (planner picked exact scans). Scaling-guide item: `hnsw.iterative_scan` on pgvector ≥ 0.8, version-gated. |
| L8 | Low | `scan_pii`'s `\d{10,11}` matches inside longer digit runs; `cleanup` scans all tables regardless of `--tables`. | `store.py:1088`, `__main__.py:358` | Code reading. |

## Decisions (defaults adopted by the plan)

| Decision | Default | Why |
| --- | --- | --- |
| Which `agent_context` values write (M4) | New key `write_contexts`, default `primary,cron` | API-gateway minions arrive as `primary`; cron jobs are real work; subagent output reaches the parent via `on_delegation`. |
| Case-fold identities (M7) | Yes, lowercase in `normalize_identity`; `remap` existing mixed-case themes | README convention is already lowercase; breaking after 1.0. |
| Uniqueness on `md5(content)` (M1) | Yes, migration 005 | Removes the size ceiling; duplicate semantics unchanged. |
| Python API surface | `MemoryStore` and all modules are internal | Semver covers config, tools, CLI, schema. |
| M5 on the 1.0 path | No — 1.1/1.2 | 1.0 is a contract release. |
| Support matrix | Python 3.11–3.13; the Postgres/pgvector versions CI tests; a minimum hermes-agent ref | Claims CI proves. |
| Delegation row semantics (M5) | `parent_session_id` = the session that delegated; child id in metadata/edges only | Matches migration 002. |
